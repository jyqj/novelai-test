# 超长篇创作方法：从规训产线到维护故事

本目录是工作方法，不是另一组发布闸门。先按当前问题选一篇，不整包塞入写手上下文。它不新增 K-ID 或改变既有 111 块的维护登记；旧知识块按下表回到新的操作方法。

| 当前问题 | 操作文件 | 把结论放在哪里 |
|---|---|---|
| 一个概念能否长成几百万字故事 | `story-engine.md` | book 的阅读体验、主线电缆；卷的冲突结构 |
| 该用什么定式、如何不套路 | `patterns.md` | arc 的模式组合及其取舍；模板 `pattern-card.md` |
| 角色行为不可信、跨卷断情绪 | `continuity.md` | 实体关系、事实、narrative_memory；弧因果链 |
| 如何埋伏笔、回收、安排章尾 | `promises-and-hooks.md` | thread 的回收设计、任务卡创作说明 |
| 某条知识到底能否使用 | `knowledge-policy.md` | 选法理由、参数依据、反例；不改知识维护归属 |
| 该怎样验证这一套有用 | `../protocol/evaluation.md` | 冷读记录、对照文本、作者反馈，不伪造读者数据 |

## 一次完整创作的主回路

阅读体验与开放问题 → 人物/世界/冲突共同生成 → 关键场景试写 → 远期承诺、近期行动 → 因果与信息呈现两张计划 → 场景写作 → 独立冷读与连续性审阅 → 正文证据回写 → 更新后续计划。

既有 init、stage、court、brief、commit 命令保持可用。S1–S4 是管理入口，不意味着人物、世界与结构只能单向依次创造。发现相互约束时回到具体问题，不靠继续填表消化矛盾。

## 三条底线

已经写进正文的事实不能被未经解释的计划覆盖；作者的明确选择不能被模板的默认口味覆盖；审美结论不能因为写了数值或多个 AI 赞同就变成科学定律。

下列属于本轮提出的创作方法，尚不是实证质量保证。成功案例与失败案例都要留存。使用既有事务与事实保护，但不新增评分准入、篇幅配额或平台自动发布。
