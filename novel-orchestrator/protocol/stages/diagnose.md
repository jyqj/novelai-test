# stage:diag — 诊断 / 学理深读 配套知识包 · 唯一有权进 knowledge/ 的阶段

| 键 | 值 |
|---|---|
| 阶段 | diag：症状归因 / 学理深读 / 用户求教 / 判据卡维护前研究 |
| 进入 | 同目标失败 ×2 · 深评/反馈点名症状复发 · check 疑难 FAIL 无从下手 · 用户求教 |
| 退出 | 结论回流（下表三去向之一）后**读完即弃**——深读内容不进简报、不进任何常规附件 |
| 本包读者 | 编排者本人（唯一执行人；不 spawn「深读代理」） |

## 诊断五步（预算 ≤2 块/次，硬约束）

1. **先归症状**：按 `knowledge-index.md` §二 2.0 症状域枚举归入闭集（structure/character/
   conflict/world/skill_system/craft/genre/webnovel），复合症状取 primary。
2. **症状→K-ID**：查 `knowledge-index.md` 对应小节（§二场景索引 / §四高频诊断）。
3. **K-ID→锚点**：`knowledge-blocks.md` 查来源与章节，按 `<!-- 锚点 -->` 取段
   （L2 操作步骤优先，L3 原理仅在归因不明时读）。
4. **读 ≤2 块**：一次诊断最多 2 块；不够说明症状没归对，回步骤 1，不加预算。
5. **结论回流**（三去向，必择一落盘）：

| 去向 | 条件 | 动作 |
|---|---|---|
| 设计层修订 | 归因指向弧/卷/设定 | `task add revise_design <node> --evidence`（先过否决案台账，court §4） |
| 蒸馏进判据 | 教训 ≥2 次复现 | `task add revise_rubric style --evidence`（workflow §6；只动项目侧 style.md） |
| 记账不动工 | 单例/证据不足 | lessons 台账一行（下次复现即够立项） |

## 禁止

- 借诊断之名浏览目录扩集（knowledge-blocks 检索协议）；整文件通读；
- 把深读原文抄进简报/评审附件/协议文件（skill 侧判据卡维护走 orchestration §6.2）；
- 替评审角色「补课」——评审只裁判据卡，诊断结论经任务与台账生效，不经转述生效。

## 学理求教（用户问「为什么/怎么学」）

同样走 症状/主题 → `knowledge-index.md`（其 P1–P6 流程索引可当学习课纲）→ 按块取段作答；
预算同上，答完即弃，不留常驻上下文。
