# 知识库三维索引（v1 收编，v2 适配）

> 本文件提供流程索引、场景索引、快速定位表和高频问题诊断四个维度的导航。
> 所有知识块的详细定义见 `knowledge-blocks.md`（含**检索协议与锚点用法**），实际内容见 `knowledge/` 目录。

## v2 使用权限与阶段映射（先读本节）

- **只在两种情形打开本文件**：① 诊断疑难（症状→K-ID，用「四、高频问题诊断」与「二、场景索引」）；
  ② 用户求教/学习导航。**常规运行期归属以 `knowledge-map.md` 为准**——运行期读 rubrics，
  庭审附件按 knowledge-map 场次白名单投递；与本文件流程索引冲突时以 knowledge-map 为准。
- 本文件正文沿用 v1 的 P1–P6 阶段编号（收编自 legacy），对照 v2 工序按下表换算：

| v1 阶段 | v2 工序 |
|---|---|
| P1 蓝图 | 书庭 S1（概念/类型/主控思想） |
| P2 粗纲 | 书庭 S2（世界）+ S3（人物/主线）+ S4（分卷） |
| P3 序列纲 | 卷庭 + 弧规划 |
| P4 人物/世界定稿 | 书庭 S2/S3 产出的实体卡与 world 定稿、facts 台账 |
| P5 章纲 | 排批（章任务卡）；traditional 另有细纲工序（modes/route-traditional.md §2） |
| P6 正文 | 写作产线（protocol/pipeline.md）；对应知识大多已蒸馏进 rubrics，勿在产线拉块 |

- 深读预算与锚点读法：见 `knowledge-map.md` 防膨胀规则与 `knowledge-blocks.md` 检索协议。
  K-ID → 文件位置的解析一律走 `knowledge-blocks.md`。

### 2.1 结构问题

| 症状 | 可能原因 | 诊断路径 | 解决方案块 |
|------|----------|----------|-----------|
| 主线散漫，越写越偏 | 树形结构思维；缺乏引线 | 检查是否有电缆结构 | K-CONCEPT-010, K-CONCEPT-011 |
| 节奏拖沓，读者走神 | 过渡性情节过多；冲突密度不足 | 检查场景转折频率 | K-STRUCT-019, K-STRUCT-012 |
| 高潮无力，结尾平淡 | 负面价值未充分递进；危机不够两难 | 检查负面价值层级 | K-STRUCT-015, K-CONFLICT-005, K-STRUCT-014 |
| 开头无聊，进入故事太慢 | 激励事件延迟或不够动态 | 检查激励事件设计（网文换算层） | K-STRUCT-008 |
| 中段塌陷，二幕冗长 | 中间点缺失或无效 | 检查序列7-12设计 | K-STRUCT-005, K-STRUCT-011 |
| 支线喧宾夺主 | 支线比例过大或未收束 | 检查支线管理三原则 | K-CONCEPT-012 |
| 因果链断裂 | 事件间逻辑不连贯 | 检查故事脊椎 | K-STRUCT-017, K-STRUCT-009 |

### 2.2 人物问题

| 症状 | 可能原因 | 诊断路径 | 解决方案块 |
|------|----------|----------|-----------|
| 人物扁平无记忆点 | 塑造等于性格，没有矛盾 | 检查塑造vs深层区分 | K-CHAR-001, K-CHAR-008 |

| 人物没有成长感 | 弧光缺失或断裂 | 检查弧光五步对齐 | K-CHAR-005 |

| 所有角色反应雷同 | 没做两极分化 | 检查场景中的角色反应 | K-WORLD-009 |

| 人物关系静态 | 关系没有演变 | 检查关系设计 | K-CHAR-009, K-CHAR-007 |

### 2.3 冲突问题

| 症状 | 可能原因 | 诊断路径 | 解决方案块 |
|------|----------|----------|-----------|
| 张力不够 | 对抗力量太弱 | 检查力量总和设计 | K-CONFLICT-006, K-CONFLICT-003 |

## 四、高频问题诊断

### 诊断流程模板

```
症状识别 → 初步归类（§2.0 闭集） → 查阅对应场景索引 → 定位知识块 → 
读取L1概念确认方向 → 读取L2操作获取步骤 → 必要时深入L3/L4
```

### 诊断案例

#### 案例1："我的故事写到中间就不知道往哪写了"

**诊断路径**：
1. 症状归类 → 结构问题：主线散漫
2. 查阅场景索引2.1
3. 可能原因：树形结构思维 + 缺乏引线
4. 定位知识块：K-CONCEPT-010（电缆理论）→ K-CONCEPT-011（引线系统）
5. 操作：
   - 读取 `knowledge/01-构思阶段/02-主线与主题设计.md` 第二章2.2节，理解电缆结构
   - 检查当前主线是否有明确的"电缆主线缆"
   - 检查是否设计了引线（反派主线）
   - 用三阶段理论（跳棋→博弈→象棋）校准引线进度

#### 案例2："读者说我的反派太弱了"

**诊断路径**：
1. 症状归类 → 冲突问题：反派薄弱（连载中后期取 `conflict.escalation`）
2. 查阅场景索引2.3
3. 可能原因：反派是符号而非角色 + 对抗力量不足；连载期还需查梯队与预埋
4. 定位知识块：K-CONFLICT-004（反面人物五步法）→ K-CONFLICT-003（战败狗原则）→ K-CHAR-012（反派梯队与轮换）
5. 操作：
   - 读取 `knowledge/02-设计阶段/04-冲突与对抗力量.md` 第五章，用五步法重新设计反派
   - 检查对抗力量总和是否大于主角力量（每卷重判）
   - 连载期：检查下任反派是否 ≥2 次预埋、是否连续两卷同一变奏型

#### 案例3："网文开篇数据很差"

**诊断路径**：
1. 症状归类 → 网文特有问题：开篇留不住人
2. 查阅场景索引2.8
3. 可能原因：三道弃读门失守 + 激励事件不够动态 + 缺乏钩子
4. 定位知识块：K-CONCEPT-020（三道弃读门）→ K-WRITE-020（开头三段钩）→ K-STRUCT-008（激励事件）
5. 操作：
   - 按前 3 秒/前 300 字/前 3 章逐门检查（首屏卖点、300 字反预期、第 3 章前主线引爆）
   - 检查前 3 章每章是否 ≥1 小爽、章末钩全勤
   - 用高概念一句话测试：能否让人一句话就对故事产生兴趣？

#### 案例4："技能体系设计出来但读者反馈升级没有成就感"

**诊断路径**：
1. 症状归类 → 技能体系问题：升级无感
2. 查阅场景索引2.5
3. 可能原因：只有数值增长 + 代价机制单一 + 只用一种升级模式
4. 定位知识块：K-WORLD-014（六种升级模式）→ K-WORLD-013（代价机制）→ K-WORLD-016（修炼境界）
5. 操作：
   - 读取 `knowledge/03-世界构建/02-技能设计.md` 第三章，检查是否组合了多种升级模式
   - 检查代价是否只有蓝条消耗，引入不可数值化代价
   - 将境界设计为认知质变而非数值跳跃
   - 升级的强度感是否落地：对照战力锚定表（K-WORLD-022）给升级一次"用武之地"

#### 案例5："故事说教感太重，读者反映主题生硬"

**诊断路径**：
1. 症状归类 → 冲突问题：说教
2. 查阅场景索引2.3
3. 可能原因：反思想被压抑 + 好人太好坏人太坏
4. 定位知识块：K-CONFLICT-002（思想vs反思想）→ K-CONCEPT-016（规避说教）→ K-CONFLICT-004（反面人物五步法）
5. 操作：
   - 读取 `knowledge/01-构思阶段/02-主线与主题设计.md` 第五章5.4节，检查思想辩证平衡
   - 过说教检查清单（第八章8.4节）
   - 强化反面人物，让其"几乎无所不能、快要得手"
   - 确保主控思想通过事件证明而非对白宣讲

#### 案例6："世界观设计了很多但读者说感受不到"

**诊断路径**：
1. 症状归类 → 世界观问题：设定堆砌无感
2. 查阅场景索引2.4
3. 可能原因：日常生活层缺失 + 解说方式生硬 + 剂量超标
4. 定位知识块：K-WORLD-010（日常生活构建与章级剂量）→ K-WORLD-007（身体现象学）→ K-WRITE-001（展示不告诉）
