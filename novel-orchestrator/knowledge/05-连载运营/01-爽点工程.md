## 一、爽点类型学与密度

**适用场景**：P3 为每序列标注爽点意图、P5 章纲编排 `payoff_entries`、P6 写回 `realized`；diagnose「爽点空转/长期无释放」时按本块对账。

### 1.1 六种爽点类型（与 `payoff_entries.kind` 枚举一一对应）

| kind | 情绪内核 | 触发条件（无此条件=空转） | 设计步骤要点 |
|------|----------|--------------------------|--------------|
| `dopamine` 即时爽 | 压抑→释放 | 前文已积累明确压抑（轻视/亏欠/挑衅），读者可指认 | 先压后放；压抑与释放同章或隔 1–2 章；释放动作公开可见（须有见证者） |
| `upgrade` 升级 | 投入→回报 | 成长轴已有可见投入（修炼/代价/资源消耗） | 提升结果可验证（对照 K-WORLD-022 锚定表）；升级后 1–2 章内给一次「用武之地」 |
| `reveal` 揭示 | 悬念→解惑 | 已有悬念账户（Thread `mystery`/`fuse` 达 `payoff_ready`） | 揭示须重排已知事实的意义，不只是补新信息 |
| `reversal` 反转 | 预期→颠覆 | 前文 ≥2 次暗示已诱导读者形成稳定预期 | 反转须回溯可信（预埋证据链）；禁无预埋硬反转 |
| `emotion` 情感 | 积累→共鸣 | 关系线已有推进记录（relationship Thread ≥2 次 advance） | 用具体动作/细节兑现，不用抒情段直陈 |
| `humor` 幽默 | 紧张→松弛 | 位于高压段落之后 | 幽默锚定角色声纹（K-CHAR-013），不齣戏、不打断张力主线 |

（`other` 为 schema 兜底值，不做设计目标。）

### 1.2 操作步骤

1. 排卷/排章前，按六型清点本卷可用爽点素材，逐条核对触发条件。
2. P5 为每章写 `payoff_entries`：`kind` + `intent`（一句话）+ 关联 `thread_ids` / `sequence_ref`。
3. 按密度基准校验窗口：**3 章 ≥1 小爽；10 章 ≥1 大爽**。大爽=改变主角处境或公开位阶的释放（通常为 `upgrade`/`reveal`/`reversal` 且伴随处境跃迁）。
4. 按章型调整：开篇章（前 3 章）每章 ≥1 小爽；铺垫/过渡章可豁免小爽，但连续豁免 ≤1 章且须含期待动作（K-STRUCT-021）；高潮章可多型叠加但 ≤3 条（防稀释）；卷末章必含 ≥1 大爽。
5. 同型递减对策：**同 kind 连续命中 ≥3 章即违规**，第 3 章起换型或升维（同型内加码不算换型；原理见 K-STRUCT-012 回报递减）。
6. P6 写回 `realized`；未兑现条目移入后续章或写明原因后删除，禁止静默丢弃。

### 1.3 可判定标准

| 检查项 | 通过判据 |
|--------|----------|
| 小爽密度 | 任意连续 3 章窗口内 ≥1 条 `realized=true` |
| 大爽密度 | 任意连续 10 章窗口内 ≥1 条处境级释放 |
| 换型 | 同 kind 连续 ≤2 章 |
| 台账完整 | 每章 `payoff_entries` ≥1 条且 P6 已回写 `realized` |
| 铺垫可指认 | 每条爽点能指出其压抑/投入/悬念来源（章号或 `thread_id`） |

### 1.4 示例（泛化）

都市异能连载第 41–50 章窗口：41 章 `upgrade`（异能进阶，烧掉三章积累的材料）→ 42 章 `dopamine`（当众驳回轻视者，压抑源自 39 章）→ 44 章 `emotion`（队友因此还清旧誓）→ 46 章 `reveal`（进阶副作用暴露幕后组织的标记，`thread_ids` 挂幕后线）→ 48 章 `reversal`（一直资助主角的商人正是标记持有人，45/47 章各有一次暗示）→ 50 章大爽（卷级对决胜利+位阶公开）。六型轮换、10 章两次处境级释放、每条可指认铺垫来源。

## 二、期待感链条

**适用场景**：P5 期待链自检（连续低 payoff 章触发）；diagnose「读者没有想追的东西/追读断裂」。与 K-STRUCT-020 的关系：爽点管「兑现那一下」，期待链管「兑现之间读者为什么留下」。

### 2.1 四拍循环操作法

1. **承诺**：向读者亮出一个可预期的价值目标（新目标/新威胁/新谜面/新关系张力）。承诺须具体可想象——「拿到秘境入场资格」优于「变强」。
2. **升级**：兑现前至少推进一次，三选一：加码（赌注变大）、加险（障碍变强）、加料（新信息使期待更具体）。
3. **兑现**：正面兑现，或「兑现但变形」（得到了，但代价/形态出人意料）；每次兑现对应一条 `payoff_entries`。
4. **新承诺**：兑现的同一章或次章内，开出 ≥1 个新期待——**期待账户守恒：每兑现一个，必须新开至少一个**。

### 2.2 期待账户

账户余额 = 当前未兑现且读者可感的承诺数。健康区间 **2–5**：主线级 1 条（贯穿本卷）、中线 1–2 条（5–15 章）、短线 1–2 条（1–5 章）。余额 >5 读者记不住且兑现压力堆积；<2 追读动力不足。跨章承诺登记为 `Thread(kind=promise)`（`plant_at` 用复合键）；章内小期待只进 `payoff_entries.intent`，不建线。

### 2.3 断裂检测判据

| 信号 | 判定与处置 |
|------|-----------|
| 连续 3 章无「升级/新开」动作 | 黄灯：下一章必须补一拍 |
| 连续 5 章既无新承诺也无升级 | 违规：期待链断裂，转 diagnose |
| 兑现后同章+次章均未开新承诺 | 违规：账户漏项，补开 |
| 承诺开出后 >15 章无任何推进 | 转 Thread 对账（防止变成悬置死线） |

### 2.4 与 Thread 的分工

期待链=读者情绪账（读者主观上「在等什么」）；Thread=情节事实账（客观上「埋了什么、何时收」）。一条 `must_not_drop` 的 Thread 可以长期静默，期待链却不允许静默——它的审计对象是「读者此刻的追读理由」。两账通过 `Thread(kind=promise)` 与 `payoff_entries.thread_ids` 互查：情绪账断了先查事实账是否有可提前激活的存货。

### 2.5 示例（泛化）

修行文：承诺「三个月后宗门大比，败者逐出」（章 12）→ 升级「对手提前突破，且买通执事换签」（章 15，加险）→ 兑现变形「大比获胜，但被迫暴露隐藏功法，长老起疑」（章 19）→ 新承诺「长老暗查主角来历」+「大比名额引出秘境资格」（章 19–20 双开）。全程账户余额 ≥3，兑现即新开。
