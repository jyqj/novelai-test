# 创作方法纠正说明（2026-09-20）

基线：PR #5 的 d29fd450eff951e16cd832791b03ce4ad16a1402，tree=f35d5e8f77370a145b897434a9f4b054a9376878。它尚未合并 main；本轮保留其历史记忆、事务与评审工作，不把旧 main 的所有问题重新算成本轮新增修复。

## 已实施

新增 methodology 操作手册并从 SKILL、阶段包、设计庭、章任务与评审接入；原知识的符号本体、解释效率等同、单一主线工具论、主题预证、压力唯一、期待守恒、信息量三分法等主张改写；对应索引同步。

模式改为按维度组合；五种旧 id 保留兼容，classic24 节点仍可参考但不必填满；模板新增体验契约、试写、因果/读者路径、回收意义与后果。人物、伏笔、关系可发展，不由固定比例和次数证明有效。

读者冷读与知情编辑分离；设计预测不当成正文证据；深评可质疑原设计。世界硬/软不再混同规则可随意破例；人物信念与世界事实区分。

仅调整与这些方法直接冲突的运行行为：旧 3/10 窗口不再 FAIL；promise 总数不再据 2–5 评级；未填/未实现章尾钩给诊断而非强制；可选 creative_brief 沿现有任务渲染进入简报。没有新增准出门槛、分布式系统或平台发布功能。

## 兼容与边界

旧项目不自动重写正文、人物或台账。模板新增字段先用于新设计，现有项目按需逐项补充。旧的具体作者约定仍需尊重；若希望改变作者已采用的节奏，应先修订项目计划而非静默豁免。

回收设计、读者状态和因果图是编辑工作表与方法，不是已经实现的自动推理数据库。工具保留 PR #5 的事实、获知与 narrative_memory 功能。本轮没有进行真实模型长篇创作、真实读者盲评或百万字压力验证；工程测试只能验证没有破坏已有工作路径。

## 检验方式

既有七套测试文件未修改，全部重跑通过。新增 test_methodology.py 的六个回归用例检查创作简报传递、无悬崖钩子的完整收束、已回收线索的后果召回、模板日志边界、零承诺与低爽点窗口不误阻断，以及事实保护未被放宽。静态对账保留 111 个知识主锚及其引用。实际结果见 METHODOLOGY_TEST_RESULTS.md；测试通过不代表文学质量获证。


`context_threads` 可列仅供历史/后果参考的 thread id，不向终态线发送推进 op。简报按目标章历史状态召回，并将选中线的“回收设计”单列为编辑计划，不能当成已发生真相；现有依赖哈希与预算纪律仍适用。
